DECISIONS

1. Use a pre-existing guardrails solution for privacy protection rather than building one from scratch, since 'a lot of people' are already thinking about it.
2. Ravi will fork the Archivist One repo rather than clone and push directly to it.
3. Steer toward using a Node.js task to kick off the LLMs, consistent with how the rest of the Veracel repo is managed with Node/JavaScript-based server-side work.
4. RAG is no longer viewed as essential given how large LLM context windows have become, so the team will expand on the existing chat repo work rather than reinvent the RAG process.
